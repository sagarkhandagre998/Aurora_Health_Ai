1 · Executive Overview

Aurora is a cross-platform health-tracking app whose distinguishing feature is "Aurora", a warm, voice-first AI companion that can act on the user's behalf — logging water, sleep, habits and meals, generating recipes, and surfacing personalised daily insights. The system follows a strict thin-client / secure-edge design: the mobile app holds no third-party API keys, and every sensitive operation is proxied through authenticated Supabase Edge Functions.

Thin ClientExpo RN app — UI, state, device sensors
Secure Edge5 Deno functions — AI, voice, insights
Managed DataPostgres + RLS, per-user isolation
External AILLM, STT & TTS via provider fallback

Design principles

  • Keys never leave the server. Client ships only public Supabase + Google OAuth IDs; all LLM/voice keys live in Supabase secrets.
  • Provider resilience. Every AI call uses a primary→fallback chain (Cerebras→Groq, Groq→OpenAI, ElevenLabs→device speech) with exponential-backoff retries.
  • Agentic, not chatty. The companion uses tool-calling to mutate real data, then confirms in natural language.
  • Offline-tolerant device sync. HealthKit / Health Connect data is de-duplicated and merged into a persisted Redux store.
  • Per-user data isolation enforced at the database layer via Row-Level Security on every table.

5 · Backend — Supabase Edge Functions

All functions: POST · verify JWT via supabase.auth.getUser() · scope queries to the user · read secret keys server-side.

6 · The AI Companion Pipeline

A single user turn through ai-companion. The agent loop runs up to 5 iterations until the model stops requesting tools.

Authenticate. Verify Bearer JWT → auth.getUser(); reject if invalid.
Load context. Parallel reads: profile (name, goals), today's water sum, latest sleep, today's habit completions & meals, 5 most-recent health_memory notes.
Build system prompt. Aurora persona + the user's name & live stats + recent observations + scope guard (health-only) + speech-friendly style rules.
Call LLM. Cerebras gpt-oss-120b with messages + 8-tool schema, reasoning_effort: low. On 429/5xx → backoff retries → fall through to Groq.
Branch on finish_reason. If tool_use → execute each tool against the DB, append results to history, loop back to step 4. Otherwise → take the final text.
Optional TTS. If useVoice, POST replyText to /tts and attach audioBase64.
Respond. Return { replyText, actions[], audioBase64? }. Client plays audio, refreshes Redux, animates the affected screen.

Provider strategy. Voice turns prefer Groq (fast LPU inference); text turns prefer Cerebras (stronger reasoning). Both speak the OpenAI Chat Completions dialect, so the same message/tool format works across providers — the fallback is a drop-in swap.
Safety rails. Max 5 agent turns prevents infinite tool loops · scope guard keeps Aurora on health topics · all tool writes are user-scoped & RLS-enforced · recipe JSON is parsed defensively (first balanced object, numeric coercion).

8 · Data Model & Security

Postgres, managed by Supabase. Every table keys off auth.users and carries an "own-rows" RLS policy (auth.uid() = user_id).

TableKey columnsNotes / relationships
profilesid (PK=auth.users), name, age, gender, height_cm, weight_kg, wake_time, bedtime, activity_level, goals[], notification_prefs, onboarding_completeauto-created by handle_new_user() trigger on signup
water_logsuser_id, amount_ml, logged_at, source, hk_uuidsource+hk_uuid dedup HealthKit imports
sleep_logsuser_id, date, duration_min, quality, source, hk_uuidunique(user_id, date) — one night/day
habitsuser_id, name, icon, frequency, target_per_day, statusactive / paused
habit_completionsuser_id, habit_id, date, countunique(habit_id, date)
mealsuser_id, name, meal_type, calories, protein_g, carbs_g, fat_g, logged_atmanual or AI-logged
meal_plansuser_id, name, diet_type, macros, ingredients[], steps[], loggedAI recipe output (nutri-coach)
streaksuser_id, type, current, longest, last_datePK(user_id, type)
health_memoryuser_id, observation, created_atfeeds AI system prompt (continuity)
insightsuser_id, text, category, created_atdaily generated card
Triggers. handle_new_user() seeds a profile row on auth signup; set_updated_at() refreshes profiles.updated_at on every update.
Defence in depth. Even though edge functions use the service-role key, RLS policies still scope every table to the owning user — a logic bug cannot leak another user's health data.
